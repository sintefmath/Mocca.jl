Process files ​

A process can be read from and written to a JSON file with read_process and write_process, and an adsorbent with load_adsorbent and save_adsorbent. Mocca has a library of both from published studies:

julia
using Mocca
library_processes()     # "haghpanah_2013_four_stage_vsa", ...
library_adsorbents()    # "zeolite_13x_haghpanah_2013", ...
process = read_process("haghpanah_2013_four_stage_vsa")
write_process("my_vsa.json", process)

Conventions ​

  • Numbers are plain SI: Pa, K, m, s, mol, kg, J. A number may also be a string with a unit, such as "0.1 bar", "25 °C", "14.45 cm", "-36.6 kJ/mol" or "100 cm/s".

  • Compositions and per-component values are objects keyed by component name, such as {"CO2": 0.15, "N2": 0.85}. Components left out of a composition get a trace ().

  • Unknown keys are errors, so that a misspelt setting is not silently ignored. Errors say where they are, such as MoccaInputError in step 3 (blowdown) of the cycle, to: ....

  "columns": {

The sections:

SectionContents
componentsOptional: components not known to Mocca, each with name, molar_mass, heat_capacity and viscosity, and optionally formula and cas.
gasThe Gas: its components in order (the first is the one to capture), and optional overrides.
feedThe Feed: composition, temperature, pressure and optionally light_product.
adsorbentsBy name: an adsorbent object (as in an adsorbent file), the name of a library adsorbent, or the path of an adsorbent file relative to the process file.
columnsBy name: Column objects. A column for beds meshed across the radius also has radial_conductivity and wall_heat_transfer.
unitsBeds, in order, as in add_bed!. thermal is "with_wall", "adiabatic" or {"type": "isothermal", "temperature": ...}. A bed meshed across the radius has radial_cells, and optionally radii (the ring edges, from 0 to the column radius) and radial_dispersion.
devicesDevices, in order, as in add_device!: a role, and at (a [unit, port] pair) or, for a link, from and to. An optional boundary sets pressure, temperature and composition.
cyclesteps, a list of steps; or sequences, a list of {"label": ..., "steps": [...]} run side by side, and an optional cycle_time.
time_steppingSee TimeStepping.
optionsSee Process.
initial_statePer bed: any of pressure, temperature, wall_temperature and composition.
parametersPer unit: Jutul parameters to override.
variablesDesign variables (see add_variable!), each with places: {"step": ..., "field": ..., "sequence": ...}, {"feed": "pressure"} or {"unit": ..., "parameter": ...}.

Steps ​

Each step has a type and its fields as keys:

typeStepFields
pressurisePressuriseduration, to, from, source ("feed" or "light_product"), bed, device, ramp_rate, conductance, name
adsorbAdsorbduration, one of velocity, superficial_velocity and flow_rate, pressure, bed, feed_device, outlet, conductance, name
blowdownBlowdownduration, to, from, through, device, bed, ramp_rate, conductance, name
evacuateEvacuateas blowdown
purgePurgeduration, one of velocity, superficial_velocity and flow_rate, pressure, bed, conductance, name
equaliseEqualiseduration, beds, device, conductance, name
idleIdleduration, bed, name
concurrentConcurrentsteps, name

Step types defined with register_step! are read and written the same way.

An adsorbent file ​

json
{
  "format": "mocca-adsorbent",
  "version": 1,
  "name": "zeolite 13X",
  "reference": "Haghpanah et al. (2013)",
  "density": 1130.0,
  "heat_capacity": 1070.0,
  "particle_diameter": 0.002,
  "particle_porosity": 0.35,
  "tortuosity": 3.0,
  "adsorbed_heat_capacity": {"CO2": 697.5687, "N2": 1096.4},
  "isotherm": {
    "type": "dual_site_langmuir",
    "reference_temperature": 298.15,
    "basis": "volume",
    "components": {
      "CO2": {"qsb": 3489.44, "b0": 8.65e-7, "dUb": -36641.21, "qsd": 2872.35, "d0": 2.63e-8, "dUd": -35690.66},
      "N2": {"qsb": 6613.551, "b0": 2.5e-6, "dUb": -15800.0}
    }
  }
}

basis is "volume" for capacities in mol per m³ of adsorbent or "mass" for mol/kg. Isotherm types defined with register_isotherm! are read the same way.

The earlier format ​

Mocca.parse_input reads the JSON files of Mocca 0.1.0 into constants structs, and convert_constants turns those into the objects above, to move such inputs over. Mocca no longer simulates them directly.
